# G31: compare (A)

The two proposals reproduce all twelve and agree on SB-20, SB-23, SB-24 and UI-16 to the line. The differences that matter:

| Bug | A's | B's | Better, and why |
|---|---|---|---|
| SB-07 | `rule_flow` returns `rules`; `network_graph` returns `reactions`; both captions read them; `VIEW_VERSION` 2 to 3; the Model view's svg label says "model: ...". | `rules` on the flow (with a fallback to the drawn count); the network caption read from the API's own counts; no version bump. | A's. The views are cached by model text and VIEW_VERSION. Without the bump, a model drawn before the fix keeps its cached flow without `rules`, so B's fallback shows the old "1 rule" until the model is edited (criterion 1). B's network caption from the API is as good as A's. |
| SB-18 | Saves only what differs from disk; Fill, Simulate and Upload save an edited data.exp but never name it. | Saves only what differs; `replaced=("data.exp",)` skips data.exp entirely for Fill and Simulate. | A's. `simulate_data` reads data.exp's time rows from disk ("keeping its time rows"), and the fill keeps its header ("data.exp gives its header only"). With B's change, a student who edits the weeks or header in the editor and presses Simulate gets the old ones, and then loses the edit when data.exp is rewritten (criterion 2). The bug asks that the notice not name data.exp, not that its edits be dropped. |
| SB-19 | Pointer: "Not started: this computer cannot fit yet; the notice above the editor says why." Given only when the page will show that notice (`machine_problem()`); else the full reason as before. | Pointer: "... The notice under Save says what to do." | A's: the alert is rendered before the editor card, above the toolbar that holds Save, so "under Save" points the wrong way. A's guard keeps a refusal from pointing at nothing when the page's shorter probe would not show it. |
| SB-21 | Lower-case labels ("particles", "weeks of data"), as the table's own header ("run setting", "compared run") and the "data" row. | Capitalized ("Particles", "Data rows"). | A's, for one case on one table; minor. |
| SB-22 | `shipped_state(...)["dataset"]`; Donors in words: "both donor banks", "FluSurv-NET donors only", "admissions donors only", "no donors: the plain filter". | `dataset_start` in the route; "both streams", "FluSurv-NET only", "admissions only", "none qualified". | Either. A's "no donors: the plain filter" says what the identity state forecasts. |
| SB-25 | Inline singulars. | `_weeks(n, what)`. | B's helper reads better (criterion 4). Take it. |
| SB-26 | Last 256 KB of each .err. | Last 64 KB. | Either. 64 KB is plenty for a student's zip; take B's. |
| UI-19 | Root cause: in model-views.js `network()`, a helper `function box(x, y, w, h)` hoists over the `box` parameter. So `box.clientWidth` is undefined, and every flow and network drawing is laid out 640 units wide, whatever the card's width. The helper is renamed; a `textScale()` (root font / 16) divides the drawing units. | `min-width` on the svg (its width × root/16) and `.mv{overflow-x:auto}`. | A's. B's keeps the 640-wide layout and stops it shrinking. So a 521 px desktop card now scrolls sideways at 100% text, where it did not, and the zoom buttons (absolute in `.mv`) scroll away with it (criteria 1 and 2). The svg's `touch-action:none` also takes the phone's sideways swipe. A's lays the drawing out to the card's own width: 14 px labels on a 332 px phone with no scroll, 22 px at 160%. |

Vote: combine. A's patch, with B's `_weeks` helper (SB-25) and B's 64 KB cap for the runner messages (SB-26). Tests from both, de-duplicated into one test_sandbox_polish.py.
