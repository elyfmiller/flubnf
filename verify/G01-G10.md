## New findings

1. FC-06 left on one form (G02, S2 like FC-06). /retro's Run form has a
   visible number field "runners" (`name="width"`, min 1, max 16 here).
   Typing 2e0, which the browser accepts (checkValidity true), then Run
   retrospective (Resume in the start-over prompt): the page becomes
   /retro/run with the raw JSON 422
   `{"detail":[{"type":"int_parsing","loc":["body","width"],…,"input":"2e0"}]}`.
   - Root cause: `app/ui/routes/retro.py` `retro_run`, `width: int = Form(4)`.
     G02's decision noted it and named G23, but no G23 bug lists it (RE-12,
     RE-13, RE-24 and RE-25 are other things), so the loop would never fix it.
   - It is the only visible number field still typed int. The others
     (`weeks_to_nowcast`, `members`, `drop_same_day`) are hidden.
2. RE-14's note on a replay with no US cell (G08, S4). The 2-state
   2026-27 replay (national off) reads "Pooled relWIS covers the 2 replayed
   jurisdictions; the US national cell is scored apart and never joins the
   pooled average." That replay has no US cell at all, so the second half
   names something the page does not have.
   - Root cause: `us_national.pooled_scope_note` always names a US cell.
   - Small: the clause could drop when the record fitted no US and none is
     aggregated. Low priority; I'd take it only if B agrees.
